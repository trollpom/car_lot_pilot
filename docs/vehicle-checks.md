# Проверка истории автомобиля в «Автомобильных торгах»

`car_lot_pilot` использует существующий сервис **ШАССИ / check_cars** как отдельный локальный компонент. Проверка запускается и результат читается в карточке лота. Next.js-провайдеры, их парсеры и генератор демо не переносились и не переписывались на Python.

## Что делает связка

1. Администратор открывает лот и раздел «История автомобиля · ШАССИ».
2. VIN берётся из карточки. Если его нет, можно ввести VIN или госномер; дополнительный номер используется для источников такси. Если у лота уже есть VIN, проверять вместо него другой автомобиль нельзя.
3. Выбирает реальные источники либо явно помеченное синтетическое демо.
4. Для live подтверждает передачу идентификатора. Платные источники требуют разрешения владельца в `.env` и отдельного согласия в форме.
5. Python-сервер вызывает защищённый endpoint ШАССИ. Браузер получает только ответ основного сервиса, без интеграционного токена и ключей провайдеров.
6. Проверяются контракт ответа, VIN, режим и срок действия. Краткий отчёт сохраняется в отдельные SQLite-таблицы и показывается в карточке: факторы риска, известные сведения, покрытие и источники.
7. Пользователь сопоставляет историю с описанием и фото, проверяет неясности на осмотре и только затем изучает ИИ-анализ и экономику участия.

Нет автоматических запросов при парсинге, получении писем или простом открытии карточки. Сведения лота и почтовые интеграции не изменяются. Отчёт не передаётся DeepSeek автоматически. Индекс истории — не вероятность выигрыша торгов и не гарантия юридической чистоты.

## Подключение на своём компьютере

Нужны обновлённые локальные копии обоих проектов. `check_cars` — приватный компонент владельца, а не общедоступная ссылка для жюри. Для его клонирования требуется ваш доступ к GitHub. Копии удобно расположить рядом:

```text
projects/
  car_lot_pilot/
  check_cars/
```

В `check_cars` установите зависимости и соберите приложение (Node.js 20.9+, проверка выполняется на Node.js 24):

```bash
npm ci
npm test
npm run build
```

В активированном Python-окружении `car_lot_pilot`:

```bash
python -m pip install -r requirements.txt
python scripts/configure_vehicle_checks.py ../check_cars
```

Скрипт создаёт общий случайный интеграционный токен в игнорируемых `car_lot_pilot/.env` и `check_cars/.env.local`, не печатая значение. Он сохраняет настроенные ключи DeepSeek/Apipoint и параметры почты. Если уже заданные интеграционные токены различаются, скрипт отказывается их перезаписывать. На Unix файлы получают права `0600`; на Windows защитите доступ своей учётной записью.

Затем в двух терминалах:

```bash
# Терминал 1, папка check_cars
npm start -- --hostname 127.0.0.1

# Терминал 2, папка car_lot_pilot, активированное Python-окружение
python scripts/serve.py
```

Штатный ШАССИ слушает порт 3000, основной сервис — порт из `EFRSB_PORT` (по умолчанию 8000). В `.env` основного сервиса должен быть задан собственный `ADMIN_PASSWORD` для входа. Публичный сервер не создаётся: оба приложения следует запускать на loopback. Не размещайте незащищённый самостоятельный API `check_cars` в интернете с платными ключами; новый токен защищает именно интеграционный endpoint.

## Настройки

| Параметр | Где | По умолчанию / назначение |
| --- | --- | --- |
| `CHECK_CARS_BASE_URL` | основной `.env` | Пусто — интеграция отключена. Скрипт задаёт `http://127.0.0.1:3000` |
| `CHECK_CARS_INTEGRATION_TOKEN` | оба сервиса | Одинаковый секрет минимум из 32 символов, только на серверах |
| `CHECK_CARS_ALLOW_PAID` | основной `.env` | `0`; `1` разрешает показ отдельного платного согласия |
| `CHECK_CARS_DAILY_LIMIT` | основной `.env` | `10` новых live-попыток за скользящие 24 часа; кеш не расходует лимит |
| `CHECK_CARS_TIMEOUT_SECONDS` | основной `.env` | `75`, допустимо 5–90 секунд; автоматического повтора нет |
| `CHECK_CARS_DEMO_ONLY` | основной `.env` | `0`; `1` запрещает live на демонстрационном стенде |
| `APIPOINT_TOKEN` | `check_cars/.env.local` | Необязательный ключ платного агрегатора, в основной сервис не переносится |
| `APIPOINT_PACKAGE` | `check_cars/.env.local` | Состав проверок агрегатора; фактическую стоимость уточняйте у него |
| `CHASSIS_DATA_DIR` | `check_cars/.env.local` | Необязательная отдельная папка JSON-отчётов; штатно `.data/` |

Переменные окружения процесса имеют приоритет перед `.env`. После изменения настроек перезапустите оба приложения. Для HTTP разрешены только loopback-адреса; удалённое соединение требует HTTPS без реквизитов и query-параметров в URL. Клиент не следует перенаправлениям, чтобы не отправить токен другому серверу.

Без ключа агрегатора live использует доступные открытые источники ШАССИ. Российские закрытые реестры остаются неизвестными. Если в ШАССИ подключён Apipoint, новый отчёт без платного разрешения будет отклонён до запроса к агрегатору, включая платный резолвер госномера. Кешированный интеграционный отчёт может возвращаться без нового списания.

## Безопасная демонстрация без платных запросов

При запущенном локальном ШАССИ и настроенной связке:

```bash
python demo/run_demo.py --vehicle-checks
```

Откройте `http://127.0.0.1:8781/`, войдите одноразовым демонстрационным паролем `demo-local-only`, откройте синтетический лот и раздел проверки истории. Стенд разрешает только demo-режим, платные источники и DeepSeek отключены. Выберите «Вставить учебный VIN» либо введите тестовый идентификатор. Данные отчёта целиком вымышлены, даже если VIN имеет корректный формат. Не оценивайте по ним настоящее имущество.

Обычный запуск `python demo/run_demo.py` не наследует настройки ШАССИ и не подключает проверку истории. Почта, парсинг торгов и рабочие базы не используются в обоих вариантах.

## API основного сервиса

Все новые endpoint требуют действующий `X-Admin-Token`, полученный штатным входом администратора.

- `GET /api/vehicle-checks/status` — безопасное состояние настройки без адреса сервера и секретов; сетевых запросов не выполняет.
- `GET /api/lots/{lot_id}/vehicle-check` — последний сохранённый результат только этого лота.
- `POST /api/lots/{lot_id}/vehicle-check` — одна явная проверка:

```json
{
  "request_id": "unique-request-identifier",
  "query": "XTA219050M0123456",
  "plate": "",
  "mode": "demo",
  "consent_to_external": false,
  "allow_paid": false
}
```

Пример использует синтетический VIN. Ответ содержит `check` и `reuse`: `new`, `cache`, `upstream_cache` или `idempotent`. Сохранённая запись содержит статус, даты, безопасную сводку `report` либо понятную ошибку. Полные записи владельцев, исполнительных производств, фотографии и исходные ответы провайдера в основной сервис не копируются. Публичный `GET /api/lots/{id}` историю не выдаёт.

Повтор с тем же `request_id` не запускает проверку заново; другой ввод с тем же ID даёт 409. Повтор по тому же автомобилю и режиму использует действующий кеш. В данный момент выполняется не более одной новой проверки истории. Ошибка/таймаут не вызывают автоматический повтор: провайдер мог уже выполнить запрос. При закрытии карточки сервер завершает начатый запрос и сохраняет результат.

Live-кеш хранится максимум 6 часов, demo — максимум 24 часа, с учётом более короткого срока ШАССИ. При обращении к истории или запуске сервиса просроченное содержимое удаляется; служебный журнал без полного отчёта остаётся до 30 дней. Это локальное хранение, а не многопользовательская production-система. Папка `.data` исходного ШАССИ использует собственные правила хранения.

Коды: 401 — вход; 402 — нет платного согласия в ШАССИ; 404 — лот; 409 — активная проверка/повторный ID с другим вводом; 422 — идентификатор/согласия/режим; 429 — локальный лимит; 502/503 — неподходящий ответ или недоступный сервис. Не следует автоматически повторять платные попытки после сетевой ошибки.

## Проверки разработки

```bash
python -m unittest discover -s tests -v
node --check app/static/vehicle-checks.js
# После npm ci и npm run build в check_cars:
python tests/smoke_vehicle_checks.py ../check_cars
```

Сквозной smoke-тест поднимает настоящие Next.js и FastAPI на случайных loopback-портах с временными базами и синтетическим лотом. Токены провайдеров очищены, открытые сетевые источники, почта, сбор торгов и DeepSeek отключены; тест проверяет транспорт и обработку демо, а не достоверность реестров.

DOM-тесты (опционально установленный `jsdom`): `node tests/test_vehicle_checks_ui.cjs` и `node tests/test_analysis_ui.cjs`. Это проверки модели DOM, не полноценный прогон реального браузера.
